### BF-01 · Critical — Фильтр цены ленты: фронт шлёт воны, бэк сравнивает доллары (×1350)

- **Файл**: `frontend/src/screens/Feed.tsx:184` (`usdToKrw`), `:193-194` (`buildListParams`: `price_min=usdToKrw(q.priceMin)`); контр-доказательство контракта — `app/infrastructure/db/repositories/listings_read.py:52-58` (`_usd_price_expr`: KRW→USD) и `:254-258` (`usd_price >= query.price_min`); бэк-тест `tests/catalog/test_listings.py:301` («KRW-объявление ~$22k (30M KRW / 1350) проходит price_min=20000»).
- **Баг**: 2026-10-17 (eb81476) фронт добавил конвертацию $→KRW, потому что старый бэк сравнивал raw-цены в вонах (`app/api/listings.py:70` до рефакторинга). 2026-10-22 (4d42fde) бэк нормализовал фильтр в USD — конвертацию на фронте не убрали. Фронтовые тесты (`Feed.test.tsx:264,283,399,446,452,494,500`) фиксируют протухшее поведение (`price_max=13500000`).
- **Воспроизведение (юзер)**: 1) Лента → чипс «до $10 000» → в запросе `price_max=13500000`, бэк сравнивает `usd_price ≤ 13 500 000 $` → фильтр не режет ничего: показаны машины и за $30k. 2) Лента → чипс «от $30 000» → `price_min=40 500 000` (USD) → «Ничего не найдено», хотя машины есть. 3) Шит фильтров: счётчик «N авто найдено» и «Применить» с ценой — те же неверные числа. Пресеты цены, сохранённые сигналы (чипсы 🔔), deep-link `/?price_max=…` — все задеты.
- **Фикс**: убрать `usdToKrw` из `buildListParams` (критерии уже в $ — бэк сам нормализует); обновить 7 ассертов в `Feed.test.tsx` на USD-значения; комментарий `FeedQuery` («цены в БД в вонах») поправить. Альтернатива — чинить бэк — хуже: контракт USD уже закреплён бэк-тестом и GEO (KZT/CNY/AED в `_usd_price_expr` вообще не нормализуются — см. заметку в конце).

### BF-02 · High — Любой `?query` на любом экране сбрасывает фильтры ленты (keep-alive cross-talk)

- **Файл**: `frontend/src/screens/Feed.tsx:390-396` (эффект `appliedSearch`) + `:247-277` (`deepLinkQuery` игнорирует неизвестные ключи и возвращает `{}`).
- **Баг**: лента живёт в keep-alive и слушает `location.search` всего приложения. Эффект применяет `deepLinkQuery(search)` к любому непустому search, даже состоящему только из чужих параметров: `deepLinkQuery("?tab=history")` → `{}` → `setQuery({})` — сброс фильтров + фоновая перезагрузка ленты (новая object-identity объекта `query` триггерит `load(query, true)`).
- **Воспроизведение**: 1) Лента → включить чипс «🇦🇪 ОАЭ» (или цену/пресет) → таб «Авто» → сегмент «История» (URL `/auto?tab=history`) → вернуться на Главную: фильтры сброшены, лента перезагружена «Все». 2) Карточка лота → «Доставка и растаможка» (`/calc?price=…&year=…`) → Назад: фильтры ленты сброшены (search `?price=…` тоже состоит из не-feed ключей). 3) `/sell?edit=N`, `/compare?v=…`, deep-link `/auto?tab=history&similar=N` — тот же эффект.
- **Фикс**: применять deep-link только если он осмысленный: `const clean = deepLinkQuery(search); if (Object.keys(clean).length) setQuery(clean);` (пустой `clean` = чужие параметры — игнор). Плюс желательно применять только при `isFeedTab(pathname)`.

## Приложение: смежная заметка по бэку (не фронт, но влияет на GEO)

`_usd_price_expr` (listings_read.py:52-58) нормализует только KRW: `CASE currency='KRW' THEN price/1350 ELSE price` — т.е. KZT/CNY/AED-цены сравниваются как будто они USD (12.2M KZT ≈ «$12.2M»). Для сортировки и price-фильтров по странам KZ/CN/AE это отдельный дефект бэка — фронт здесь ни при чём, но после фикса BF-01 фильтры по этим странам будут неточными, пока бэк не расширит нормализацию курсами из `lib/fx` (KZT 480, CNY 7.1, AED 3.6725 — значения уже дублированы на фронте).
