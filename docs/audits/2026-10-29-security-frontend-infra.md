# Аудит безопасности: frontend / бот / инфра-контур

**Дата:** 2026-10-29 (сводка 2026-10-28)
**Объём:** волны NAV-V2 (лендинг/Shell/чаты-таб) и GEO-V1 (lib/geo.ts, чипсы стран, fx-курсы, SellCar страна/город, MyLotsPanel) + смежные контуры (aiogram-бот, docker-compose, nginx, Caddy, Centrifugo, gateway, CI, зависимости).
**Метод:** только чтение кода, доказательства «файл:строка». Запуск Docker/npm/тестов и сетевые проверки не выполнялись.

## Сводка

Общая гигиена фронта хорошая: React-рендер экранирует пользовательские данные везде, markdown чатов идёт через DOMPurify с жёстким allowlist, initData верифицируется HMAC на бэке, подписки Centrifugo авторизуются subscribe-proxy на бэке, SSRF-фильтр link-preview строгий, внутренние API за X-Internal-Token, в CI стоят pip-audit и bandit, прод-config имеет fail-fast на дев-секреты.

Основные риски смещены в **инфру и хранилище**: (1) prod-оверлей docker-compose не закрывает порты MinIO с захардкоженными `minioadmin/minioadmin` и translate-сервиса без токена — а опубликованные Docker-порты обходят ufw из bootstrap.sh; (2) JWT access+refresh и партнёрский API-ключ лежат в localStorage — единая XSS-эскалация на 30-дневную сессию; (3) HTML-инъекция в сообщениях бота через неэкранированные make/model лота (parse_mode=HTML по умолчанию).

**Итог: 18 находок — P1: 1, P2: 6, P3: 11.**

## Чек-лист по сферам

### 1. XSS — чисто (2 периферийных замечания)
- **Markdown чатов:** `frontend/src/lib/markdown.tsx:17-56` — DOMPurify с `ALLOWED_TAGS` (без img/iframe/script), `ALLOWED_ATTR: ["href","title"]`, хук `afterSanitizeAttributes` ставит `target=_blank rel=noopener noreferrer` (:38-47). Схемы URI фильтруются дефолтным `ALLOWED_URI_REGEXP` DOMPurify (javascript:/data: вырезаются). Использование единственное dangerouslySetInnerHTML в кодовой базе — markdown.tsx:61; все три потребителя (Message.tsx:83, AdminChatRoom.tsx:73, PartnerChatRoom.tsx:107) идут через него.
- **city/country (GEO-V1):** `listings.city` — свободный текст String(64) (`app/infrastructure/db/models.py:485`, валидация только trim — `app/transport/http/routers/market.py:215-219`), но рендерится исключительно как JSX-текст: ListingCard.tsx:100-104, Listing.tsx:469-475, MyLotsPanel.tsx:275-282 — React экранирует. `country` валидируется паттерном `^[A-Za-z]{2}$` (market.py:204); флаги/имена — из статического словаря `frontend/src/lib/geo.ts:22-44`. Инъекций нет.
- **Фото-URL:** onError-обработчики только меняют state (ListingCard.tsx:283), никаких URI-манипуляций. `<img src>` с пользовательских URL — трекинг-риск PHOT-01, не XSS.
- **Имена тредов/сообщений, ответы AI, partner showcase:** ChatList.tsx:83, ChatRoom.tsx:636, partner-карточки (PartnerScreens.tsx:477,1769,2243) — JSX-текст/атрибуты, `rel="noreferrer noopener"` на внешних ссылках. Чисто.
- Замечания: BOT-01/BOT-02/BOT-03 — HTML-инъекции на стороне **бота** (Telegram-разметка), не веб-XSS.

### 2. Токены/хранилище — находки TOK-01, TOK-02, ADM-01
- localStorage: `autobot.access`, `autobot.refresh` (api/client.ts:16-17), `autobot.guest` (api/auth.ts:9), `autobot.partnerKey` (partner/api.ts:22), `autobot.theme`/`autobot.surface`/`autobot.views.*` (не чувствительны; `viewHistory.ts:25-36` декодирует JWT-payload без верификации, но `sub` используется только как ключ хранилища). Админ-токен — sessionStorage (admin/api.ts:8-9).
- **postMessage:** слушателей `message` нет вообще (grep по src — 0) — поверхность закрыта.
- **initData:** фронт отправляет только `wa.initData` на `/auth/telegram` (api/auth.ts:50-63); верификация HMAC-SHA256 по data_check_string + окно auth_date — `app/infrastructure/security/tokens.py:76-152`. `initDataUnsafe` на фронте используется для: `start_param` → строго `^listing[_-]?(\d+)$` с навигацией на свой роут (App.tsx:58-67), `user` → отображение и `bot.username` → ссылка `t.me/<bot>?startapp=listing_<id>` (external.ts:58-66). Доверия к подделке нет: доступ к API только через JWT, выданный бэком после проверки подписи.

### 3. Открытые редиректы / SSRF-клиент — чисто + EXT-01 (P3)
- Внешние ссылки чатов: `extractSoloLink` (linkPreview.tsx:74-82) пропускает только `https?://` или `/listing/\d+`; `<a href={url}>` с `rel="noopener noreferrer"` (linkPreview.tsx:143-148, 191-197).
- SSRF на бэке (OG-превью): `app/infrastructure/services/link_preview.py:32-62` — схема http/https, все адреса getaddrinfo обязаны быть публичными, ≤1 редирект с повторной проверкой, лимит 512KB. (Остаточный TOCTOU — см. гипотезы.)
- Gateway не является SSRF-прокси: target выбирается статической таблицей `services/gateway/routing.py:18-52`, путь не влияет на хост.
- `openExternal`/`window.open` без валидации схемы — EXT-01 (данные от бэка, прямого вектора сейчас нет).

### 4. Бот — находки BOT-01..03; платежи чисто
- **Транспорт:** long polling (`app/transport/bot/__main__.py:114`), вебхука нет — secret_token неприменим. Внутренняя связь с бэком — `X-Internal-Token` (client.py:96), fallback на APP_SECRET_KEY только в dev (config.py:53-56, prod запрещён :142-148).
- **pre_checkout (handlers.py:849-867):** payload валидируется структурно `sub:<id>`/`plc:<id>`; сумма инвойса формируется ботом из `backend.prepare_payment` (handlers.py:834-841, цены тарифов на бэке — payments/use_cases.py:127-133), из сообщения юзера сумма не приходит. **successful_payment (handlers.py:870-934):** ConfirmPayment проверяет `record.user_id == user_id` (payments/use_cases.py:174-175) и идемпотентен по `status=='paid'` — повторный вебхук не продлевает дважды. Двойной клик «купить» в боте гасится кулдауном 10с (handlers.py:824-846).
- **Deep-links (handlers.py:388-455):** `listing_<N>` → int() с отловом ValueError; `login_<code>` → одноразовый код подтверждает бэк (state_hash против session fixation, routers/auth.py:21); `ref_*` только логируется. Экранирование карточек — `build_listing_caption` (handlers.py:285-289) корректно экранирует title/price/details/source. Неэкранированные места — BOT-01/02/03.
- **Inline-режим** (handlers.py:370-385): query строго `^listing[_:\-\s]?(\d+)$`, ответ — та же санитизированная карточка.

### 5. Инфра-конфиги — находки INFRA-01..05, HDR-01, CI-01

## Гипотезы (не доказано кодом, требует проверки в рантайме)

1. **TOCTOU/DNS-rebinding в link-preview:** `_assert_public_host` резолвит хост через `getaddrinfo`, но httpx при коннекте резолвит повторно — в окне между проверкой и коннектом DNS может отдать приватный IP (link_preview.py:45-53 против :83-84). Вероятность низкая (окно миллисекунды), но классический residual-SSRF; лечится пином IP в коннекте или резолвером-кастомным transport.
2. **RabbitMQ guest:guest на опубликованном порту:** compose использует `amqp://guest:guest` между контейнерами (docker-compose.yml:94) — по умолчанию RabbitMQ пускает guest только с loopback; если работает, значит loopback-ограничение снято (иначе сервисы бы не коннектились) → тогда management-UI 15672 с guest:guest доступен и снаружи. Проверить конфиг rabbitmq.
3. **Прод-сценарий Centrifugo:** prod-оверлей не проксирует WS через Caddy и не публикует 8008, но профиль `realtime` в примере prod-запуска не поднимается (`--profile mono`) — как чаты работают в проде (или контур realtime просто не включён), неясно; при включении потребуется reverse-proxy WS + TLS + закрытие 8008.
4. **Фронтовый `listing.url` для лотов-партнёров:** `href={lot.url}` (PartnerScreens.tsx:485,1246) берётся из пула импорта; если парсер когда-нибудь начнёт брать URL из пользовательского поля — EXT-01 станет активным вектором.
5. **Self-signed HTTPS в dev-миниаппе (frontend/Dockerfile:13-19, entrypoint-ssl.sh):** генерация ключа в entrypoint не проверялась (файл не читали) — убедиться, что ключ не попадает в образ/логи.
